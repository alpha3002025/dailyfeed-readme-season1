
현재 메시지를 대량 발송하는 서비스를 운용중이며 레거시 메시지 파이프라인을 안정화를 수행 중입니다. 레거시 메시지 파이프라인을 개선하기 위한 문제 해결과정을 제시해주세요.

현재 고객사는 쇼핑몰, 의류 쇼핑몰, 중견 B2C 사업체, 타 IT 사업체 등 다양하며, 크리스마스,연말,설날 등에는 프로모션 이벤트가 엄청나게 많이 발생해서 시스템의 부하가 높으며, '문제 상황' 섹션에 정의한 문제가 발생하고 있고 지연이 발생하기도 합니다. 이에 따라 차기버전의 메시지 발송시스템을 개발해야 하며, 메시지 발송을 효율적으로 수행해야만 합니다. 

고객사는 우리 회사의 API 를 통해 메시지를 발송요청을 하며, 고객사 수는 300개 이상이며, 카카오 알림톡의 webhook url 응답 지연시간은 평균 5초, 최대 1시간입니다.

## 문제 상황
레거시 메시지 파이프라인 시스템은 이렇습니다.
- 대형 고객사의 캠페인 발송 시작 시 발송처리량이 느려지기 시작
- 카카오의 알림톡 webhook url 은 발송즉시 오는 케이스도 있고 1시간 이상 지연되어 오는 경우도 있습니다.
- 캠페인 중간 취소 요청이 올수 있는데 이미 큐에 들어갔을 경우 발송취소가 불가능하도록 레거시 시스템이 만들어져 있습니다. (현재 구조는 캠페인 요청을 모두 큐에 넣은 것들에 대한 소비자 로직은 큐에 있는 요청에 대해 모두 발송을 하게 되어 있습니다.)
- 발송 실패 사유가 카카오/통신사/자체 시스템 어디서 발생했는지 파악이 어려운 경우가 있습니다.

## 시스템 개선 목표
이번 버전의 프로젝트의 목표는 다음과 같습니다.
- 브랜드 사의 캠페인이 다른 브랜드 사의 일반 발송에 영향을 주지 않는다.
- 발송결과는 webhook 기준으로 정확히 1번만 반영되어야 한다.
- 캠페인 단위 취소/일시정지가 가능해야 한다. 중간에 캠페인을 고객사가 취소했을 경우 고객사에서 이미 발송된 고객들의 id와 해당 메시지를 파악가능해야 한다.
- 실패 사유를 다음과 같이 분류합니다. 
  - 카카오 통신 에러
  - 통신사 통신 에러
  - 내부 시스템 에러 (우리측 시스템 장애)
  - 사용자 수신 거부


## 추가 요구사항
다음의 요소가 만족된다면 더 좋습니다.
- 메시지 발송상황 기록 : 메시지가 정상적으로 도착했다는 것을 확인할 수 있는 관제 페이지가 있다면 좋습니다.
- A/B 테스트 : 어떤 기능으로 할때 더 효과가 좋은지를 확인할수 있다면 더 좋습니다.
